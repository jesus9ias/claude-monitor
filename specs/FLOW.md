# Spec workflow: rules for agents

Managed by ticket-spec-flow. Do not edit this file; only the author changes it.
Below, `flow` means `node specs/.flow/flow.mjs`.

- Project state lives in the general spec (`specs/general`). Start at `specs/INDEX.md` (generated, not versioned: run `flow index` if it is missing); never scan folders to find things.
- Work is defined by tickets in `specs/tickets` (`CLM-n.md`). A ticket is a delta. The general spec is the truth for implemented behavior; the latest ticket definition is the truth for work not yet implemented.
- Read only what the task needs: the index, then the spec sections involved, then the ticket (and its `touches`). Do not read closed, cancelled or obsolete tickets unless the question is historical.
- Never edit the index or script-managed ticket fields (`blocks`, `superseded_by`, `obsolete`) by hand. Use `flow` commands (`flow set`, `flow log`, `flow item`).
- Every change to a ticket's definition or metadata is logged with a reason. After editing a definition section, run `flow log <ID> refined "<reason>"`.
- When implementing a ticket: update the general spec in the same commit as the tests and code; then review the `CLAUDE.md` files in play (root, plus the ticket's subprojects) and set the ticket's `claude_md` to `updated` or `unchanged` with `flow set`.
- Tests not covered by the ticket's scenarios are protected: never modify, skip or delete them.
- Stay inside the ticket's `touches.code_scope`.
- Prefix every commit with the ticket ID (`CLM-n: ...`), also for manual work. Small changes with no behavior change use a quick ticket (`flow new <type> --quick`); work done without any ticket is registered afterwards with `flow new <type> --reconcile "<range>"`.
- Items marked `verify: manual` are confirmed by the author; never mark them as passed yourself.
- In loop runs, only run commands from `loop.allowed_commands` in `specs/flow.config.yml`; never deploy, apply, publish or delete real resources.
- Stop and ask the author when: there is a contradiction, a significant doubt, 3 failed attempts on a ticket, or a guard would be crossed. Never edit this file or any guard to get past a stop.
